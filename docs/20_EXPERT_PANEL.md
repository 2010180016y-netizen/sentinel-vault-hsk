# 전문가 회의체 기록 (3회)

구성 방식에 대한 정직한 명시: 회기님 지침의 "세계 최고 수준 전문가 회의체"는 이 작업 환경에서 외부 실명 전문가를 실제로 소집할 수 없으므로, **각 분야 최고 수준 실무자의 판단 기준·공격 시나리오를 역할로 명시한 적대적 검증 라운드**로 수행했다. 즉 5개 역할이 각자 이해가 다른 결론을 내도록 강제하고, 결론이 충돌하면 증거(체인 실측·코드·테스트)로 판정해 문서에 남겼다. 실제 인물·기관과의 통화·자문이 있었던 것처럼 읽히지 않도록 명확히 밝힌다.

패널 구성:

| ID | 역할 (판단 기준) |
|---|---|
| P1 | DeFi 퀀트·MEV 아키텍트 — 수수료·슬리피지·유동성 대비 기대수익, 실행 알고리즘 |
| P2 | 스마트컨트랙트 보안 감사관 — 공격면, 권한, 재진입, 오라클 조작, 회계 오류 |
| P3 | AI 에이전트 결제·A2A 프로토콜 설계자 — 의사표시·승인·정산의 책임 분리, 재전송·서명 가변성 |
| P4 | Web3 해커톤 심사위원 — 완성도·차별화·데모 설득력·심사 방어선 |
| P5 | 실자금 운용·리스크 운영자 — 킬스위치, 사고 대응, 자금 인출 통제, 컴플라이언스 |

# 1차 회의 — 트랙 선택과 승산 전략

**안건**: Track 1(AI Agent Trading) vs Track 2(HSP A2A Settlement) 중 어디로 갈 것인가. 그리고 무엇으로 이길 것인가.

## 검토 자료 (실측)
- Track 2는 HSP QA 엔드포인트가 우리 egress IP에서 **403**(allowlist 미등록). 가이드상 ①HSP Operations에 IP 등록 요청 ②지갑 수동 승인·테스트 토큰 충전 ③MCP 8개 도구 확인이 선행 조건. 대회 Q&A에 동일 요청이 11/21에 올라왔고 **11/24 현재 답변 0건**.
- Track 2 제출작 10건(전체 16건 중) — "mandate + gateway + attestation"이 이미 포화.
- Track 1 제출작 6건 중 **3건이 "guarded vault + TWAP/사이즈/손절"** 클러스터(Keel, SayTrade, Glassbox).
- HSKSwap 실측: 풀 5개, USDT 중심 성형 토폴로지 → **3풀 순환 경로 없음 → 삼각 차익거래 불가**. WHSK/USDT 2.8시간 스왑 10건.
- 수수료 0.3%/거래 → 왕복 0.6%.

## 각 패널 의견

**P3 (A2A 설계자)** — Track 2는 남은 8일 중 외부 allowlist 응답을 기다려야 하고, 응답이 없으면 결제 1건도 실증하지 못한다. 심사에서 "HSP로 실제 정산했다"를 증명하지 못하면 트랙 요건 위반이다. **탈락.** 대신 HSP의 설계 원칙(의도/승인/정산 분리, nonce·deadline 재전송 방지)을 Track 1 구현에 흡수하면 "HSP 생태계를 이해하는 팀"이라는 신호는 유지된다.

**P4 (심사위원)** — 심사 테이블에서 Track 1 여섯 팀 중 셋이 같은 그림이다. "우리도 볼트로 제한한다"는 **세 번째 주장**이므로 가산점이 아니라 감점 위험이 있다. 심사위원은 3분 안에 "이 팀이 남과 무엇이 다른가"를 찾는다. 남은 차별화 축은 ①**에이전트의 주장을 검증 가능하게 만드는 것**(다른 팀은 제한만 하고, 주장의 진위는 아무도 다루지 않는다) ②**실행 알고리즘의 수준**(슬라이싱·임팩트 예산) ③**실패를 정직하게 보고하는 지표**. "차익거래 봇"이라고 쓰면 3분 만에 반박당한다 — 풀이 5개뿐이다.

**P1 (퀀트/MEV)** — 수수료 30bp에 유동성 $840k면, $200 주문의 예상 임팩트는 약 5bp, 왕복 비용은 약 65bp다. 즉 **기대 엣지가 65bp를 넘지 못하면 거래하지 않는 것이 정답**이다. 대부분의 해커톤 봇은 "항상 뭔가 한다"는 것을 성과로 착각한다. 우리는 반대로 **"거래하지 않는다"는 결정을 1급 시민으로 만들고, 그 근거를 온체인에 남겨야** 한다. 또 하나: HSKSwap은 성형 토폴로지라 차익거래가 없으므로, 차익거래를 흉내내면 데모에서 들킨다. 대신 ①TWAP 대비 이탈(평균회귀) ②풀 간 내재가격 괴리(USDT 레그로 유도한 HSK 가격 vs 실제) ③유동성 대비 주문 크기 규율 — 이 셋이 정직한 알파 원천이다.

**P2 (감사관)** — 트랙 선택은 보안 관점에서도 Track 1이 낫다. Track 2는 외부 서비스(HSP Gateway) 상태에 의존해 "실패 원인이 우리 코드인지 그쪽인지" 구분이 안 되면 데모가 무너진다. Track 1은 우리 코드와 공개 체인만으로 재현된다.

**P5 (운영/리스크)** — 실자금을 다루므로 회기님 자금이 실제로 움직이는 구조는 피해야 한다. "페이퍼 우선(paper-first), 라이브는 명시적 옵트인 + 소액"이 기본값이어야 하고, 볼트에는 소유자 즉시 인출·즉시 정지가 있어야 한다.

## 판정 (1차 결론)

1. **Track 1 확정.** Track 2는 allowlist 외부 대기 + 포화 + 검증 불가 리스크로 기각. HSP의 설계 원칙은 차용한다.
2. **포지셔닝 재정의**: "차익거래 봇"이 아니라 **"자기 주장에 책임지는 에이전트(Accountable Agent)"**.
   - 다른 팀: 에이전트에게 **한도**를 준다.
   - 우리: 에이전트에게 한도를 주는 것에 더해, **에이전트가 주장한 엣지·전략 버전을 온체인에 사전 등록·선언하게 하고, 실현 결과와 대조해 공개**한다.
3. **차별화 3축 확정**
   - (A) **전략 사전등록(pre-registration)**: `strategyHash` 없는 인텐트는 실행 불가. 전략을 몰래 바꿔 성과를 꾸밀 수 없다.
   - (B) **엣지 허들(edge hurdle)**: 선언 엣지 ≥ 정책 최소 엣지(왕복 수수료+임팩트 예산 초과분). 허들을 못 넘으면 **거래하지 않는 것이 정답**이며, 그 "NO-TRADE" 결정도 기록된다.
   - (C) **임팩트 예산 기반 분할집행(parent/child slice)**: 부모 주문 예산을 정하고, 조각마다 임팩트·노셔널 상한을 지킨다. 유동성이 얕은 DEX에서 대량 주문을 던지지 않는다.
4. **정직한 지표**: `declaredEdgeSumBps` vs `realizedEdgeSumBps`, 수수료 포함 실현손익, 고점 대비 낙폭. "주장한 엣지가 실제로 났는가" 비율을 온체인에서 누구나 읽게 한다.
5. 데모는 **페이퍼 우선**으로 만들고, 라이브 경로는 소액·명시적 옵트인으로만 연다(회기님 승인 필요).

# 2차 회의 — 스마트 컨트랙트·리스크 아키텍처

**안건**: 볼트의 권한·검증 구조, 오라클, 서명, 회계, 배포 형태.

## 검토 자료 (실측)
- `IQuoterV2`는 view가 아니어서 **온체인 호출 불가**(주석 직접 확인).
- SwapRouter02 `exactInputSingle`에는 deadline이 없고 `multicall(uint256 deadline, bytes[])`로만 강제 가능(Blockscout 검증 ABI).
- HSKSwap WHSK/USDT 풀 `observationCardinality = 240` → TWAP 사용 가능.
- `slot0` 스팟은 단일 트랜잭션 내 플래시스왑으로 조작 가능.

## 각 패널 의견

**P2 (감사관)** — 가장 위험한 설계는 "에이전트가 준 견적을 믿는 것"이다. 견적은 오프체인에서 만들어지고, 지연·조작이 가능하다. 온체인에서 쿼터를 다시 부를 수 없다면, **컨트랙트가 스스로 TWAP에서 공정가를 계산해 실행가 상·하한을 결정**해야 한다. 두 번째 위험은 풀 주소 위조다. 반드시 `factory.getPool(tokenIn, tokenOut, fee)`와 일치해야 하고, 라우터·팩토리 주소는 생성자에서 immutable로 고정해야 한다. 세 번째는 토큰 승인 잔존이다. 매매 후 allowance를 0으로 되돌려야 한다.

**P1 (퀀트)** — TWAP 창은 10분 이상. 2초 블록이니 300블록이다. 240 관측 슬롯이면 600초 창은 안전하게 커버된다. 그리고 슬리피지 상한은 "TWAP 대비"로 정의해야 의미가 있다. 스팟 대비로 잡으면 조작된 스팟이 기준이 되어 규율이 무력해진다. 분할집행은 부모 단위 예산과 조각 수 상한이 없으면 무한 루프로 자금을 퍼나를 수 있다.

**P3 (A2A 설계자)** — 서명은 **이중 서명**으로 가야 한다. 전략 키(핫)와 리스크 키(콜드)가 같은 인텐트에 서명해야 실행된다. 하지만 Safe식 온체인 2-of-N은 매매마다 승인 트랜잭션이 하나 더 붙어 가스가 2배가 되고 UX가 죽는다. x402/AP2처럼 **오프체인 서명 + 온체인 단일 실행**이 정답이다. 재전송 방지는 nonce, 시간 경계는 deadline으로 명시적으로. 그리고 리스크 키는 **정지 권한만** 갖고 실행 권한은 없어야 한다.

**P5 (운영)** — 소유자는 언제든 인출할 수 있어야 한다(자금이 회기님 것이다). 대신 소유자가 정책을 바꾸면 이벤트로 남아 감사 가능해야 한다. 업그레이드 프록시는 만들지 말자. 불변이 심사에서도 유리하다("no admin override"). 위급 시 소유자·리스크 키 둘 다 즉시 `pause` 가능해야 한다.

**P4 (심사위원)** — 컨트랙트가 500줄을 넘으면 심사위원은 읽지 않는다. **핵심 함수 하나(`executeIntent`)와 뷰 하나(`stats`)로 서사를 만드는 구조**가 좋다. 주석에 "다른 팀과 무엇이 다른가"를 코드 안에서 바로 보이게 써야 한다.

## 판정 (2차 결론) — 확정 아키텍처

1. **불변(immutable) 볼트, 프록시 없음.** 라우터·팩토리·쿼트토큰·소유자는 생성자 고정.
2. **이중 오프체인 서명**: `strategySigner` + `riskSigner`가 동일 EIP-712 인텐트에 서명 → 온체인에서 두 서명 모두 검증. 리스크 키는 `pause`만 가능.
3. **TWAP 자기검증**: `executeIntent`가 풀 `observe(twapWindow)`로 평균 tick을 구하고, `factory.getPool`로 풀 주소를 재확인하고, TWAP 기준 `fairOut`을 계산해 `minAmountOut ∈ [fairOut·(1−maxSlippage), fairOut]`을 강제. 에이전트 견적은 신뢰하지 않는다.
4. **스팟–TWAP 괴리 게이트**: `|spotTick − twapTick| ≤ maxSpotTwapDeviationBps`. 조작·이상 상태에서 자동 정지.
5. **노셔널·일일한도·쿨다운·낙폭**: 쿼트토큰(USDT) 기준으로 계산(쿼트토큰이 아닌 자산은 TWAP 환산). 낙폭 초과 시 **위험 축소(매도)만 허용**.
6. **엣지 허들**: `declaredEdgeBps ≥ minEdgeBps` 강제, 실현 엣지는 사후 계산해 누적 → 주장 vs 실현 공개.
7. **부모/자식 분할집행**: `openParent`로 예산 선언, 자식 조각은 `spent + notional ≤ budget`, `slices < maxSlices`.
8. **회계**: 쿼트토큰 기준 실현손익·수수료·평균단가·고점(high-water)·낙폭. `equity()`는 TWAP 평가.
9. **안전장치**: `nonReentrant`, `forceApprove` 후 실행·실행 후 allowance 0 복구, 실행 후 잔고 델타 ≥ minOut 재검증(Safe Guard의 사후검사 차용), 즉시 `pause`.
10. **라이브 기본값 = 꺼짐.** 오프체인 실행기는 paper가 기본, live는 환경변수 + 인텐트별 확인.

→ 3차 회의는 구현·테스트 후 실제 코드와 감사 도구 출력을 대상으로 적대적 검증한다(→ `docs/20_EXPERT_PANEL_S3.md`).
