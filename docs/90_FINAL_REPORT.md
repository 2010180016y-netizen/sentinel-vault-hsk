## 2. 트랙 판단 — 왜 Track 1인가

**Track 2(HSP A2A) 기각 근거(실측)**
- HSP QA MCP 엔드포인트 `https://mcp-qa.hashkeymerchant.com/health` → 본 환경에서 **HTTP 403 Cloudflare 차단**. 가이드 1단계가 "팀의 공인 egress IP를 HSP Operations에 등록"이므로 정상 차단이지만, 등록은 **주최 측 응답 대기**가 필요합니다.
- 추가로 지갑 수동 승인·테스트 토큰 충전(팀의 수동 작업)이 선행되어야 첫 결제가 가능합니다.
- Track 2 제출작이 이미 **10건**이고 전부 mandate/gateway/attestation 구조로 포화.
- 남은 8일 중 외부 응답 대기는 통제 불가 리스크 → 403을 뚫으려 시도하지 않고 기각.

**Track 1 경쟁 구도(중요)**
- 제출작 6건 중 **3건이 "가드 볼트 + TWAP 슬리피지 + 일일손실 + 쿨다운"** (Keel, SayTrade, Glassbox). 같은 그림으로 가면 세 번째 주장이 되어 감점 위험.
- HSKSwap 실측: 풀 5개가 USDT 중심 성형 토폴로지 → **3풀 순환 경로가 없어 삼각 차익거래가 불가능**. "차익거래 봇"으로 쓰면 3분 만에 반박당합니다.

**그래서 잡은 포지션 — "Accountable Agent"**
1. **전략 사전등록**: 사람이 등록한 `strategyHash` 없으면 실행 불가 → 성과를 꾸미려 전략을 몰래 바꿀 수 없음
2. **선언 엣지 vs 실현 엣지 온체인 대조**: `edgeCredibilityBps()` — 주장한 엣지가 시장에서 버틴 비율
3. **노-트레이드도 결정**: 허들 미달로 거래하지 않은 사실을 온체인에 기록
4. **임팩트 예산 기반 부모/자식 분할집행**

## 3. 구현물

### 3.1 스마트 컨트랙트 `src/SentinelVault.sol` (17,308 bytes, 불변·프록시 없음)

- **이중 오프체인 서명(EIP-712)**: `strategySigner` + `riskSigner` 둘 다 서명해야 실행. 리스크 키는 `pause`만 가능, 인출·재가동 불가. Safe식 온체인 2-of-N 대신 단일 트랜잭션으로 처리해 가스 2배 문제 회피.
- **TWAP 자기검증**: `QuoterV2`는 view가 아니어서 온체인 호출 불가(원문 주석 확인) → 컨트랙트가 풀 `observe(600s)`로 평균 tick을 구해 `fairOut`을 **스스로** 계산. `minAmountOut ∈ [fair×(1−1.5%), fair]` 강제. 에이전트 견적은 신뢰하지 않음.
- **스팟–TWAP 괴리 게이트**(기본 500bp, 1 tick≈1bp) — 플래시스왑 조작 차단.
- **정책**: 1회 200 USDT(매도는 ×4까지), 롤링 24h 800 USDT(매수만 계상), 낙폭 15%(초과 시 매도만 허용), 쿨다운, 부모주문 예산·조각 수.
- **사후 검증**: 라우터가 보고한 `amountOut`과 실제 잔고 증가분이 **일치**해야 하고 `≥ minOut`. 불일치 시 `OutputMismatch`.
- **승인 위생**: `forceApprove` 후 매매 뒤 0으로 복구. `factory.getPool`로 풀 주소 재확인. `nonReentrant`.
- **회계**: 수수료(쿼트 단위), 평균단가, 실현손익, 승수, 고점, 선언/실현 엣지 누적 → `stats()` 한 번으로 심사위원이 다 읽음.

### 3.2 AI 에이전트 `agent/` (Python, 의존성 web3·eth-account만)
`rpc`(체인 177 강제) → `market`(TWAP·실견적·스왑 이벤트 바) → `signals`(평균회귀+추세+흐름+변동성, 결정적) → `policy`(컨트랙트 규칙 미러, 가스 낭비 방지) → `intent`(EIP-712 이중 서명, 온체인 digest와 대조 테스트) → `executor`(페이퍼 기본 / 체인) → `ledger`(회계·지표) → `core`(루프·설명) + `chat`/`server`/`web`(대화형 대시보드).

| 구분 | 결과 |

**테스트가 잡은 실제 버그 3건** (그대로 두면 데모가 무너졌을 것):
1. `uint64` 금액 필드 오버플로 — 18자리 자산은 200 USDT만 해도 uint64 초과 → `uint128`로 확장
2. 손실 제한이 청산을 막는 역설 — 매도에도 1회 한도를 적용해 낙폭 구간에서 청산 불가 → 매도 상한 확대, 일일 한도는 매수만
3. 쿨다운이 첫 거래를 영구 차단(`lastTradeAt == 0`)
